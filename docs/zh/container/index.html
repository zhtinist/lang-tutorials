容器操作对照 · C++ / Python / Go / Java

同一件事(求长度、判断元素是否存在、插入、删除、遍历),四门语言的写法和语义都不一样,而且不只是语法皮肤不同——背后是每门语言不同的内存模型和设计取舍(可参照各自教程的「变量与内存模型」章节)。这组笔记把”数组/列表”“哈希表/集合”“字符串”“栈/队列”这几类容器最常用、最容易搞混的操作按同一个维度并排列出来。

先看这张表:求长度

四门语言连”怎么问一个容器有多长”都不统一——有的是方法、有的是字段、有的是全局函数:

容器 C++ Python Go Java
定长数组 sizeof(a)/sizeof(a[0]) (无定长数组类型) len(a) a.length(字段,无括号)
动态数组/列表 v.size() len(v) len(s) list.size()(方法,有括号)
字符串 s.size() / s.length()(等价,按字节) len(s)(按 Unicode 码点) len(s)(按字节,UTF-8 编码后) s.length()(按 UTF-16 code unit)
哈希表/字典 m.size() len(m) len(m) m.size()

记忆点:Java 里数组用 .length 字段、容器类(List/Map/String)用 .length()/.size() 方法,这个不一致是 Java 历史包袱(数组是语言原生类型,早于 Collections 框架);其余三门语言至少在”是不是方法”这件事上是自洽的。C++/Java/Python 的字符串长度都各自按不同的单位计数(字节 / UTF-16 单元 / 码点),只有 Go 明确按字节——这些差异详见 strings.md。

再看这张表:判断元素/键是否存在

这是最容易踩坑的一类操作,因为”存在性检查”在几门语言里的失败模式完全不同——有的报错、有的返回一个容易和”真实存在的默认值”混淆的哨兵值,是本专题里最需要小心的差异:

场景 C++ Python Go Java
数组/列表查值 find(v.begin(),v.end(),x)!=v.end() x in lst 手写循环(无 in) list.contains(x)
哈希表查 key m.contains(k)(C++20)/ m.count(k) k in d v, ok := m[k] map.containsKey(k)
查不存在的 key 会怎样 m[k] 静默插入一个默认值! d[k] 抛 KeyError m[k] 返回零值,不报错也不插入 map.get(k) 返回 null(和”值本身是 null”无法区分)

最后一行是本表的重点,也是四门语言里唯一一处”处理方式各不相同、且都不直观”的地方,maps-and-sets.md 里会用实测代码逐条拆解每一种行为背后的原因。

使用建议

  • 这不是又一套语言教程,是横向对照的速查手册——不需要通读,遇到”这个操作在 XX 语言里怎么写”时直接查对应文件里的表格。
  • 每一条对比结论都经过实际编译/运行验证(C++ 用 clang++ -std=c++20,Python 3.9,Go 1.26,Java 25),不是凭记忆写的。
  • 想搞懂”为什么会有这些差异”而不只是记住写法,配合各语言教程的「变量与内存模型」章节一起看效果最好——容器行为的分歧,根子上都是每门语言值/引用语义选择的直接推论。
