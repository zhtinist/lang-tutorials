# 异常处理

本章覆盖 C++ 异常处理的核心知识点:`try`/`catch`/`throw` 基本语法、标准异常类层次、自定义异常类、`noexcept` 关键字、异常安全保证的三个等级,以及构造函数/析构函数中抛异常的特殊规则。

## 一、`try`/`catch`/`throw` 基本语法

```cpp
#include <iostream>
#include <stdexcept>

double divide(double a, double b) {
    if (b == 0) {
        throw std::invalid_argument("除数不能为 0"); // throw 抛出一个异常对象
    }
    return a / b;
}

int main() {
    try {
        std::cout << divide(10, 2) << "\n";
        std::cout << divide(10, 0) << "\n";     // 这里会抛异常,后面的代码不再执行
        std::cout << "这行不会被打印\n";
    } catch (const std::invalid_argument& e) {    // 按类型匹配捕获,更具体的异常类型放前面
        std::cout << "捕获 invalid_argument: " << e.what() << "\n";
    } catch (const std::exception& e) {             // 兜底捕获所有标准异常
        std::cout << "捕获 exception: " << e.what() << "\n";
    } catch (...) {                                   // 捕获任意类型的异常(包括非 std::exception 派生的)
        std::cout << "捕获未知异常\n";
    }

    std::cout << "程序继续正常运行\n";
}
```

```
5
捕获 invalid_argument: 除数不能为 0
程序继续正常运行
```

要点:`catch` 子句按书写顺序依次匹配,应该**从最具体的异常类型排到最泛化的类型**(反过来会导致后面更具体的 `catch` 永远不会被匹配到,某些编译器会警告);异常对象建议按 `const 引用` 捕获(避免拷贝、避免对象切割);`catch (...)` 捕获任何类型(包括非 `std::exception` 派生的类型,比如直接 `throw 42;`),通常用作最后一道兜底,无法获取具体错误信息。

## 二、标准异常类层次

`<stdexcept>`/`<exception>` 定义的标准异常都派生自 `std::exception`,核心接口是虚函数 `const char* what() const noexcept`:

```
std::exception
├── std::logic_error       —— 程序逻辑错误(理论上可在运行前避免)
│   ├── std::invalid_argument
│   ├── std::out_of_range
│   ├── std::length_error
│   └── std::domain_error
├── std::runtime_error     —— 只有运行时才能检测到的错误
│   ├── std::range_error
│   ├── std::overflow_error
│   └── std::underflow_error
├── std::bad_alloc          —— operator new 分配失败
├── std::bad_cast            —— dynamic_cast<T&> 失败
└── std::bad_function_call    —— 调用空的 std::function
```

```cpp
#include <iostream>
#include <stdexcept>
#include <vector>

int main() {
    try {
        std::vector<int> v{1, 2, 3};
        v.at(10);            // std::out_of_range,派生自 std::logic_error -> std::exception
    } catch (const std::out_of_range& e) {
        std::cout << "out_of_range: " << e.what() << "\n";
    }

    try {
        std::string s = "abc";
        int n = std::stoi(s); // std::invalid_argument,派生自 std::logic_error
        (void)n;
    } catch (const std::invalid_argument& e) {
        std::cout << "invalid_argument: " << e.what() << "\n";
    }

    try {
        throw std::runtime_error("运行期错误示例"); // std::runtime_error 也派生自 std::exception
    } catch (const std::exception& e) {
        std::cout << "runtime_error via exception: " << e.what() << "\n";
    }
}
```

```
out_of_range: vector
invalid_argument: stoi: no conversion
runtime_error via exception: 运行期错误示例
```

## 三、自定义异常类

自定义异常应继承 `std::exception`(或其某个子类),并覆盖 `what()`(注意 `what()` 本身必须是 `noexcept` 的,因为异常处理过程中再抛异常是危险操作):

```cpp
#include <iostream>
#include <exception>
#include <string>

class InsufficientFundsError : public std::exception {  // 自定义异常:继承 std::exception
public:
    InsufficientFundsError(double requested, double available)
        : msg_("余额不足:需要 " + std::to_string(requested) +
               ",可用 " + std::to_string(available)) {}

    const char* what() const noexcept override {           // 必须覆盖 what(),且带 noexcept
        return msg_.c_str();
    }

private:
    std::string msg_;
};

void withdraw(double amount, double balance) {
    if (amount > balance) {
        throw InsufficientFundsError(amount, balance);
    }
}

int main() {
    try {
        withdraw(100, 50);
    } catch (const InsufficientFundsError& e) {
        std::cout << "捕获自定义异常: " << e.what() << "\n";
    } catch (const std::exception& e) {
        std::cout << "捕获标准异常: " << e.what() << "\n";
    }
}
```

```
捕获自定义异常: 余额不足:需要 100.000000,可用 50.000000
```

要点:`what()` 返回的 `const char*` 必须在异常对象的整个生命周期内保持有效(通常存成 `std::string` 成员,`c_str()` 返回其内部缓冲区指针,不能返回局部临时字符串的指针)。

## 四、`noexcept` 关键字

`noexcept` 是函数签名的一部分,向调用者(以及编译器/标准库)承诺"这个函数不会抛出异常":

```cpp
#include <iostream>
#include <vector>
#include <stdexcept>

void mayThrow() { throw std::runtime_error("oops"); }
void neverThrows() noexcept { /* 承诺不抛异常 */ }

struct Movable {
    Movable() = default;
    Movable(Movable&&) noexcept { std::cout << "移动构造(noexcept)\n"; } // 标注 noexcept 很关键
};

int main() {
    std::cout << std::boolalpha;
    std::cout << "noexcept(mayThrow())=" << noexcept(mayThrow()) << "\n";     // false,noexcept() 运算符检测函数是否声明为不抛异常
    std::cout << "noexcept(neverThrows())=" << noexcept(neverThrows()) << "\n"; // true

    // vector 扩容时:如果元素的移动构造函数是 noexcept,vector 用移动;否则为了强异常安全退回用拷贝
    std::vector<Movable> v;
    v.reserve(1);
    v.emplace_back();
    v.emplace_back();  // 触发扩容,因为 Movable 的移动构造是 noexcept,这里用移动而不是拷贝
}
```

```
noexcept(mayThrow())=false
noexcept(neverThrows())=true
移动构造(noexcept)
```

违反 `noexcept` 承诺(在标注了 `noexcept` 的函数里实际抛出异常且未被内部捕获)会导致**立即调用 `std::terminate`**,不会走正常的异常传播/捕获流程:

```cpp
void f() noexcept {
    throw std::runtime_error("破坏 noexcept 承诺");
}
int main() { f(); }
```

```
libc++abi: terminating due to uncaught exception of type std::runtime_error: 破坏 noexcept 承诺
```

（进程以 SIGABRT 异常终止,退出码 134,而不是被 `catch` 捕获——这也是编译器会针对这种代码给出 `-Wexceptions` 警告的原因。）

`noexcept` 的实际意义:标准库容器(如 `std::vector`)在扩容等需要"搬迁元素"的操作中,只有当元素类型的移动构造函数是 `noexcept` 时才会使用移动(否则为了保证异常安全,退回使用拷贝,即使拷贝更慢)——这是"移动构造函数应尽量标 `noexcept`"这条实践建议的根本原因。

## 五、异常安全保证:基本 / 强 / 不抛

按照能提供的保证从弱到强,异常安全分为三个等级:

| 等级 | 保证内容 |
|---|---|
| **基本保证**(basic guarantee) | 异常抛出后,对象仍处于**合法但不确定**的状态(不变量成立,可以安全析构或重新赋值,但具体内容不可预期),不会内存泄漏或数据损坏 |
| **强保证**(strong guarantee) | 异常抛出后,对象状态**完全回滚**到调用前,操作要么完全成功要么完全没发生("事务性"),通常靠"先在临时副本上操作,成功后再原子性地交换/提交"实现 |
| **不抛保证**(nothrow guarantee) | 承诺绝不抛出异常,通常用 `noexcept` 标注,析构函数、`swap`、移动构造应尽量满足这一等级 |

```cpp
#include <iostream>
#include <vector>
#include <stdexcept>

class SafeStack {                      // 强异常安全示例:push/pop 失败时状态完全不变
public:
    void push(int v) {
        data_.push_back(v);             // std::vector::push_back 本身提供强异常安全保证
    }
    int popAndProcess(bool simulateFailure) {
        int top = data_.back();
        if (simulateFailure) {
            throw std::runtime_error("处理失败"); // 抛异常前还没有修改 data_,状态保持不变(强保证)
        }
        data_.pop_back();
        return top;
    }
    size_t size() const { return data_.size(); }
private:
    std::vector<int> data_;
};

int main() {
    SafeStack s;
    s.push(1);
    s.push(2);
    std::cout << "size before=" << s.size() << "\n"; // 2

    try {
        s.popAndProcess(true);    // 模拟失败
    } catch (const std::exception& e) {
        std::cout << "捕获: " << e.what() << "\n";
    }
    std::cout << "size after failed pop=" << s.size() << "\n"; // 仍是 2 —— 强异常安全:失败不改变状态

    int v = s.popAndProcess(false);
    std::cout << "popped=" << v << " size=" << s.size() << "\n"; // popped=2, size=1
}
```

```
size before=2
捕获: 处理失败
size after failed pop=2
popped=2 size=1
```

## 六、构造函数与析构函数中的异常

**构造函数抛异常是允许且常见的**(用来报告"对象无法被正确构造"),此时该对象被认为从未存在过——它自己的析构函数**不会**被调用,但它**已经构造完成的成员/基类子对象**会被自动逆序析构:

```cpp
#include <iostream>
#include <stdexcept>

struct Resource {
    Resource(int id) : id_(id) {
        if (id == 2) throw std::runtime_error("构造函数中抛异常");
        std::cout << "构造 Resource " << id_ << "\n";
    }
    ~Resource() {
        std::cout << "析构 Resource " << id_ << "\n";
    }
    int id_;
};

struct Holder {
    Resource a{1};    // 先构造成功
    Resource b{2};     // 构造失败抛异常 —— 此时 a 已经构造完成,C++ 保证会自动析构 a
    Resource c{3};      // 不会被构造
};

int main() {
    try {
        Holder h;
    } catch (const std::exception& e) {
        std::cout << "捕获: " << e.what() << "\n";
    }
}
```

```
构造 Resource 1
析构 Resource 1
捕获: 构造函数中抛异常
```

**析构函数原则上不应该抛出异常**:如果一个异常正在栈展开(unwinding)过程中传播,而展开路径上某个对象的析构函数又抛出了新的异常,C++ 无法决定该传播哪一个异常,会直接调用 `std::terminate` 终止程序。因此析构函数内部如果调用了可能抛异常的操作,应该自己 `try/catch` 妥善处理(通常是记录日志后吞掉),而不是让异常穿出析构函数。C++11 起析构函数默认隐式是 `noexcept`,显式声明 `noexcept(false)` 才能让析构函数抛异常(几乎不应该这样做)。
