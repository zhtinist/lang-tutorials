# 变量类型与内存布局

本章覆盖 C++ 类型系统与内存模型的核心知识点:基本类型的大小、类型推导(`auto`/`decltype`)、`const`/`constexpr`/`volatile` 三个易混淆的限定符、引用与指针的全面对比、数组与指针的关系、四大内存分区、`struct` 内存对齐、位域、`union`、枚举。所有 `sizeof`/地址均为在 Apple Silicon(arm64)上实测结果,不同平台/编译器可能不同。

## 一、基本类型与占用字节

```cpp
#include <iostream>
int main() {
    std::cout << "bool: " << sizeof(bool) << " bytes\n";
    std::cout << "char: " << sizeof(char) << " bytes\n";
    std::cout << "short: " << sizeof(short) << " bytes\n";
    std::cout << "int: " << sizeof(int) << " bytes\n";
    std::cout << "long: " << sizeof(long) << " bytes\n";
    std::cout << "long long: " << sizeof(long long) << " bytes\n";
    std::cout << "float: " << sizeof(float) << " bytes\n";
    std::cout << "double: " << sizeof(double) << " bytes\n";
    std::cout << "long double: " << sizeof(long double) << " bytes\n";
    std::cout << "int*: " << sizeof(int*) << " bytes\n";
}
```

```
bool: 1 bytes
char: 1 bytes
short: 2 bytes
int: 4 bytes
long: 8 bytes
long long: 8 bytes
float: 4 bytes
double: 8 bytes
long double: 8 bytes   (x86 上通常是 16 字节,arm64 上是 8 字节 —— 标准只保证 >= double)
int*: 8 bytes            (64 位平台上所有指针都是 8 字节,与指向的类型无关)
```

标准只规定各类型的**最小取值范围**,并保证 `sizeof(char) <= sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long)`,具体字节数由平台/ABI 决定,写跨平台代码要用 `<cstdint>` 里的 `int32_t`/`uint64_t` 等定宽类型。

## 二、`auto` 与 `decltype` 类型推导

```cpp
#include <iostream>
#include <vector>

int getInt() { return 42; }

int main() {
    auto a = 5;            // int
    auto b = 3.14;          // double
    auto c = getInt();      // int
    std::vector<int> v{1,2,3};
    auto it = v.begin();    // std::vector<int>::iterator,类型名很长,auto 省心

    decltype(a) d = 10;     // int,与 a 类型完全相同
    int x = 1;
    int& rx = x;
    decltype(rx) ry = x;    // int&,decltype 对已声明变量会保留引用/cv 修饰
    decltype((x)) rz = x;   // 加一层括号后,decltype((x)) 推导为 int&(表达式规则不同)
    rz = 5;

    std::cout << "a=" << a << " d=" << d << "\n";
    ry = 99;
    std::cout << "x=" << x << " (rz sees " << rz << ")\n";
}
```

```
a=5 d=10
x=99 (rz sees 99)
```

要点:

- `auto` 用初始化表达式的类型推导变量类型(类似模板参数推导),**总是会丢弃引用和顶层 const**(除非显式写 `const auto&`)。
- `decltype(expr)`:如果 `expr` 是不加括号的变量名,得到该变量声明时的确切类型(含引用/const);如果 `expr` 是加了括号的左值表达式,结果多加一层引用。这个差异是常见的坑。
- `decltype(auto)`(C++14)结合两者:像 `decltype` 一样精确保留类型,常用于转发返回值的模板函数。
- 函数返回类型可用 `auto` 配合尾置返回类型:`auto f() -> int { ... }`,或 C++14 起直接从 `return` 语句推导。

## 三、`const` / `constexpr` / `volatile`

```cpp
#include <iostream>

constexpr int square(int x) { return x * x; } // 可在编译期求值(参数是编译期常量时)

int main() {
    const int a = 10;             // 运行期常量:值不可改,但初始值可以是运行期才知道的
    constexpr int b = square(5);   // 编译期常量:25 在编译阶段就算好,可用于数组长度等场合

    int arr[b];                    // constexpr 值可以作为数组长度(编译期已知大小)
    arr[0] = 1;

    // a = 20;                     // 编译错误:cannot assign to variable 'a' with const-qualified type

    const int* p1 = &a;            // “指向 const int 的指针”:*p1 不可改,p1 本身可以指向别处
    int c = 5;
    int* const p2 = &c;            // “const 指针”:p2 本身不能重新指向,但 *p2 可以改
    *p2 = 6;

    std::cout << "a=" << a << " b=" << b << " arr[0]=" << arr[0]
               << " c=" << c << " *p1=" << *p1 << "\n";
}
```

```
a=10 b=25 arr[0]=1 c=6 *p1=10
```

违反 `const` 的赋值会在编译期直接报错:

```
error: cannot assign to variable 'a' with const-qualified type 'const int'
    a = 20;
    ~ ^
note: variable 'a' declared const here
```

`volatile` 告诉编译器"这个变量的值可能被程序之外的因素改变(硬件寄存器、信号处理程序、多个执行流),每次访问都必须真正读写内存,不能被优化寄存器缓存或消除":

```cpp
#include <iostream>
int main() {
    volatile int flag = 0;
    flag = 1;
    std::cout << flag << std::endl;
}
```

三者对比:

| | 含义 | 求值时机 |
|---|---|---|
| `const` | 承诺不通过这个名字修改值 | 运行期或编译期均可 |
| `constexpr` | 要求能在编译期求值 | 编译期(若参数满足条件) |
| `volatile` | 每次访问都必须真读写内存,不做优化假设 | 与常量性无关,常用于内存映射寄存器 |

`volatile` **不提供线程安全**,不能替代原子操作或锁——这是初学者常见的误解。

## 四、引用 vs 指针全面对比

```cpp
#include <iostream>

void byPointer(int* p) { if (p) *p += 1; }
void byReference(int& r) { r += 1; }

int main() {
    int a = 10;

    int* p = &a;       // 指针:可以为 nullptr,可重新指向别的对象,需要解引用 *p 才能访问值
    int& r = a;         // 引用:必须初始化,一旦绑定就不能重新绑定到别的对象,用起来像别名

    p = nullptr;         // 合法:指针可以不指向任何东西

    byPointer(&a);
    byReference(a);
    std::cout << "a=" << a << "\n"; // 10 + 1 + 1 = 12
}
```

```
a=12
```

| | 指针 | 引用 |
|---|---|---|
| 是否可为空 | 可以(`nullptr`) | 不可以(语言层面保证非空,但可通过悬空引用间接违反) |
| 是否必须初始化 | 不必须 | 必须 |
| 能否重新绑定 | 可以(`p = &b;`) | 不可以(`r = b;` 是赋值,改的是 `a` 的值) |
| 是否需要解引用 | 需要 `*p` | 不需要,直接当作原对象用 |
| 能否做算术运算 | 可以(`p++`、`p+1`) | 不可以 |
| 是否有独立存储 | 是(指针本身占内存) | 语言层面看不到存储(通常实现为指针,但语义上是别名) |
| 能否指向数组元素/容器元素 | 可以 | 可以(常用于函数参数避免拷贝) |

## 五、数组与指针的关系

```cpp
#include <iostream>

void printArr(int* arr, int n) {   // 数组作为函数参数会“退化”为指针
    for (int i = 0; i < n; ++i) std::cout << arr[i] << " ";
    std::cout << "\n";
}

int main() {
    int arr[5] = {10, 20, 30, 40, 50};
    int* p = arr;               // 数组名在大多数表达式中退化为“指向首元素的指针”

    std::cout << arr[2] << " " << *(arr + 2) << " " << p[2] << "\n"; // 三种写法等价

    std::cout << "sizeof(arr)=" << sizeof(arr)      // 20:整个数组的字节数
               << " sizeof(p)=" << sizeof(p) << "\n"; // 8:指针本身的字节数

    printArr(arr, 5);

    int matrix[2][3] = {{1,2,3},{4,5,6}};
    std::cout << matrix[1][2] << "\n"; // 6
}
```

```
30 30 30
sizeof(arr)=20 sizeof(p)=8
10 20 30 40 50
6
```

要点:数组变量本身知道自己的完整大小(`sizeof(arr)` 是数组总字节数),但一旦"退化"为指针(赋值给指针变量、传给函数参数),就只剩下首地址信息,`sizeof` 结果变成指针大小——这就是"数组传参会丢失长度信息,必须额外传 `n`"的根本原因。二维数组 `matrix[i][j]` 在内存里是按行连续存储的一维块。

## 六、四大内存分区:栈 / 堆 / 全局静态区 / 常量区

```cpp
#include <iostream>

int globalVar = 100;               // 全局/静态区 —— 已初始化数据段(.data)
int globalUninit;                   // 全局/静态区 —— 未初始化数据段(.bss)
const char* strLiteral = "hello";   // "hello" 字面量本身在常量区(只读段 .rodata)

void showAddresses() {
    static int staticLocal = 1;     // 静态局部变量,也在全局/静态区,但只在首次调用时初始化
    int stackVar = 42;               // 栈
    int* heapVar = new int(7);       // 堆(需要手动 delete,否则内存泄漏)

    std::cout << "全局变量(数据段):        " << &globalVar << "\n";
    std::cout << "未初始化全局变量(BSS段): " << &globalUninit << "\n";
    std::cout << "字符串字面量(常量区):    " << (const void*)strLiteral << "\n";
    std::cout << "静态局部变量(数据段):    " << &staticLocal << "\n";
    std::cout << "栈变量:                  " << &stackVar << "\n";
    std::cout << "堆变量:                  " << heapVar << "\n";

    delete heapVar;
}

int main() { showAddresses(); }
```

实测输出(地址每次运行会变,但相对关系一致):

```
全局变量(数据段):        0x104520000
未初始化全局变量(BSS段): 0x104520014
字符串字面量(常量区):    0x1045192a8
静态局部变量(数据段):    0x104520010
栈变量:                  0x16b8e6ebc
堆变量:                  0x104ac5900
```

四大分区总结:

| 分区 | 存放内容 | 生命周期 | 分配/回收方式 |
|---|---|---|---|
| 栈(stack) | 局部变量、函数参数、返回地址 | 随函数调用/返回自动产生和销毁 | 编译器自动管理,速度快 |
| 堆(heap) | `new`/`malloc` 分配的对象 | 手动 `delete`/`free`,或智能指针管理 | 程序员(或 RAII)负责,速度较慢 |
| 全局/静态区 | 全局变量、`static` 变量 | 程序启动时分配,程序结束时释放 | 编译器/加载器管理;分 `.data`(已初始化)和 `.bss`(未初始化,值为 0) |
| 常量区 | 字符串字面量、`const` 修饰的编译期常量数据 | 程序运行全程只读 | 通常与代码段一起加载,写入会导致运行时错误(段错误) |

## 七、`struct` 内存对齐规则

编译器会按成员类型的对齐要求在结构体里插入填充字节(padding),使每个成员的地址是其对齐值的整数倍,同时结构体整体大小是最大成员对齐值的整数倍。

```cpp
#include <iostream>

struct Bad {
    char a;   // 1 字节
    int b;    // 4 字节,要求 4 字节对齐 —— a 后面被填充 3 字节
    char c;   // 1 字节 —— 结构体末尾再填充 3 字节凑成 4 的倍数
};

struct Good {
    int b;    // 4 字节
    char a;   // 1 字节
    char c;   // 1 字节 —— 只需在末尾填充 2 字节
};

int main() {
    std::cout << "sizeof(Bad)=" << sizeof(Bad) << " alignof(Bad)=" << alignof(Bad) << "\n";
    std::cout << "sizeof(Good)=" << sizeof(Good) << " alignof(Good)=" << alignof(Good) << "\n";
}
```

```
sizeof(Bad)=12 alignof(Bad)=4
sizeof(Good)=8 alignof(Good)=4
```

同样的三个成员,只因声明顺序不同,`Bad` 比 `Good` 多用 4 个字节——**把大成员放前面、小成员集中放后面**能减少 padding。可以用 `alignas` 显式指定对齐要求,用 `#pragma pack(n)` 或 `[[gnu::packed]]` 强制取消对齐(会牺牲访问性能,某些平台甚至不允许非对齐访问)。

## 八、位域(bit-field)

当一个字段的取值范围很小,可以用位域压缩存储空间(常用于协议头、硬件寄存器映射):

```cpp
#include <iostream>

struct Flags {
    unsigned int isVisible : 1;   // 只占 1 位
    unsigned int isEnabled : 1;
    unsigned int level     : 4;   // 占 4 位,取值范围 0-15
};

int main() {
    std::cout << "sizeof(Flags)=" << sizeof(Flags) << "\n"; // 编译器压到 4 字节(一个 unsigned int)

    Flags f{};
    f.isVisible = 1;
    f.isEnabled = 0;
    f.level = 9;
    std::cout << "isVisible=" << f.isVisible << " isEnabled=" << f.isEnabled
               << " level=" << f.level << "\n";
}
```

```
sizeof(Flags)=4
isVisible=1 isEnabled=0 level=9
```

位域不能取地址(`&f.isVisible` 非法),跨平台的位排列顺序(高位在前/低位在前)由实现定义,不适合做跨平台二进制协议的可移植描述。

## 九、`union`

`union` 的所有成员**共享同一块内存**,大小等于最大成员的大小,同一时刻只有一个成员是"有效"的:

```cpp
#include <iostream>

union Value {
    int i;
    float f;
    char bytes[4];
};

int main() {
    std::cout << "sizeof(Value)=" << sizeof(Value) << "\n"; // 取最大成员大小,4

    Value v;
    v.i = 65;
    std::cout << "as int: " << v.i << "\n";
    std::cout << "as char: " << v.bytes[0] << "\n"; // 65 == 'A',与 v.i 共享同一块内存

    v.f = 3.14f;
    std::cout << "as float: " << v.f << "\n";
    // 此时 v.i 已不再有意义(底层字节被 float 表示覆盖)
}
```

```
sizeof(Value)=4
as int: 65
as char: A
as float: 3.14
```

C++11 起 `union` 可以包含带构造/析构函数的类型(带来"活跃成员"的手动管理责任),现代 C++ 更推荐用 `std::variant`(见第 12 章)代替裸 `union`,能自动追踪当前活跃的类型并在类型不符时抛异常。

## 十、枚举 `enum` / `enum class`

```cpp
#include <iostream>

enum Color { RED, GREEN, BLUE };                   // 传统 enum:隐式转 int,枚举名污染外层作用域
enum class Direction { North, South, East, West };  // enum class(C++11):强类型,不隐式转换

int main() {
    Color c = RED;
    int n = c;                     // 传统 enum 隐式转 int,合法
    std::cout << "c=" << n << "\n"; // 0

    Direction d = Direction::North; // 必须加限定名
    // int m = d;                   // 编译错误:enum class 不能隐式转 int
    int m = static_cast<int>(d);    // 需要显式 static_cast
    std::cout << "d=" << m << "\n"; // 0

    enum class Status : char { Ok = 1, Fail = 2 }; // 可指定底层类型(默认是 int)
    std::cout << "sizeof(Status)=" << sizeof(Status) << "\n"; // 1
}
```

```
c=0
d=0
sizeof(Status)=1
```

要点:传统 `enum` 的枚举值会直接进入外层作用域(容易和其他常量重名),且能隐式转 `int`,是 C 遗留特性;`enum class`(C++11 强类型枚举)不污染作用域、不隐式转换、可以显式指定底层整数类型,应作为默认首选。
