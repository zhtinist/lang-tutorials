# 函数与引用

本章覆盖函数相关的核心知识点:重载、默认参数、`inline`、函数指针、lambda 表达式、`std::function`/`std::bind`、可变参数模板、参数传递方式的选择,以及返回值优化(RVO/NRVO)。

## 一、函数重载(overload)

同一作用域内可以有多个同名函数,只要参数列表(类型或个数)不同,编译器根据实参在编译期选出最匹配的一个:

```cpp
#include <iostream>

void print(int x) { std::cout << "int: " << x << "\n"; }
void print(double x) { std::cout << "double: " << x << "\n"; }
void print(const std::string& s) { std::cout << "string: " << s << "\n"; }
void print(int x, int y) { std::cout << "two ints: " << x << "," << y << "\n"; }

int main() {
    print(1);
    print(1.5);
    print(std::string("hi"));
    print(1, 2);
}
```

```
int: 1
double: 1.5
string: hi
two ints: 1,2
```

重载决议只看参数类型,**不看返回类型**——两个函数仅返回类型不同不能构成重载。

## 二、默认参数

```cpp
#include <iostream>

void greet(std::string name, std::string greeting = "Hello") {
    std::cout << greeting << ", " << name << "!\n";
}

int main() {
    greet("Alice");        // 使用默认值 "Hello"
    greet("Bob", "Hi");      // 显式提供
}
```

```
Hello, Alice!
Hi, Bob!
```

默认参数必须从右往左连续设置(有默认值的参数后面不能再跟没有默认值的参数),且只能在声明处出现一次(通常写在头文件声明里,`.cpp` 里的定义不再重复默认值)。

## 三、内联函数 `inline`

```cpp
#include <iostream>

inline int max2(int a, int b) { return a > b ? a : b; } // 建议编译器在调用点展开,省去函数调用开销

int main() {
    std::cout << max2(3, 7) << "\n";
}
```

```
7
```

`inline` 是给编译器的**建议**而非强制命令,现代编译器会自行决定是否真正内联展开(哪怕不加 `inline` 关键字也可能内联,加了也可能不内联)。`inline` 真正保证的语言层面效果是**放松 ODR**:允许同一函数定义出现在多个翻译单元中(见第 1 章),这也是类内定义的成员函数默认隐式带 `inline` 的原因。

## 四、函数指针

```cpp
#include <iostream>

int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

int apply(int (*op)(int, int), int x, int y) { // 函数指针作为参数,实现“策略”传递
    return op(x, y);
}

int main() {
    int (*fp)(int, int) = add;   // 声明一个函数指针,指向 add
    std::cout << fp(2, 3) << "\n";       // 5

    fp = mul;                     // 指针可以重新指向另一个签名相同的函数
    std::cout << fp(2, 3) << "\n";       // 6

    std::cout << apply(add, 4, 5) << "\n"; // 9
    std::cout << apply(mul, 4, 5) << "\n"; // 20
}
```

```
5
6
9
20
```

函数指针的类型语法比较绕(`返回类型 (*变量名)(参数类型列表)`),现代 C++ 里绝大多数场景可以用 `std::function` 或模板 + `auto` 替代,函数指针主要在与 C API 交互(回调函数)时还会遇到。

## 五、lambda 表达式与捕获列表

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

int main() {
    int x = 10, y = 20;

    auto byValue    = [x, y]() { return x + y; };  // 按值捕获(捕获时刻的快照,之后 x/y 再变也不影响)
    auto byRef      = [&x, &y]() { return x + y; }; // 按引用捕获(反映调用时刻的最新值)
    auto byRefAll   = [&]() { x++; return x; };      // 隐式按引用捕获所有用到的外部变量
    auto byValueAll = [=]() { return x + y; };        // 隐式按值捕获所有用到的外部变量
    auto mixed      = [x, &y]() { return x + y; };     // 混合捕获:x 按值,y 按引用
    auto mutableLambda = [x]() mutable { x++; return x; }; // mutable 允许修改按值捕获的副本(闭包对象内部持久)

    std::cout << byValue() << " " << byRef() << "\n"; // 30 30
    x = 100;
    std::cout << byValue() << " " << byRef() << "\n"; // byValue 仍是旧快照 30,byRef 反映新值 120

    std::cout << byRefAll() << "\n";    // x 变成 101,返回 101
    std::cout << byValueAll() << "\n";  // 定义时捕获的快照 10+20=30
    std::cout << mixed() << "\n";        // x 快照 10 + y 当前值 20 = 30

    std::cout << mutableLambda() << " " << mutableLambda() << "\n"; // 11 12(闭包内副本持续递增)

    auto genericAdd = [](auto a, auto b) { return a + b; }; // 泛型 lambda(C++14),等价于模板 operator()
    std::cout << genericAdd(1, 2) << " " << genericAdd(1.5, 2.5) << "\n";

    std::vector<int> v{5, 3, 1, 4, 2};
    std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; }); // lambda 作为比较器,常见用法
    for (int n : v) std::cout << n << " ";
    std::cout << "\n";
}
```

```
30 30
30 120
101
30
30
11 12
3 4
5 4 3 2 1
```

捕获列表速查:

| 写法 | 含义 |
|---|---|
| `[]` | 不捕获任何外部变量 |
| `[x]` | 按值捕获 `x` |
| `[&x]` | 按引用捕获 `x` |
| `[=]` | 隐式按值捕获所有用到的外部变量 |
| `[&]` | 隐式按引用捕获所有用到的外部变量 |
| `[=, &y]` | 默认按值,但 `y` 按引用 |
| `[this]` | 捕获当前对象指针(成员函数内),可访问成员变量 |
| `[*this]`(C++17) | 按值捕获整个当前对象(拷贝),lambda 生命周期长于对象时更安全 |
| `[x = expr]` | 初始化捕获(C++14),可以移动捕获或捕获表达式结果 |

lambda 表达式本质上是编译器生成的一个匿名类,重载了 `operator()`,捕获的变量成为这个类的成员——理解这一点就能理解为什么按值捕获在定义时"拍快照"、`mutable` 修改的是闭包对象自己的成员而非外部变量。

## 六、`std::function` 与 `std::bind`

`std::function<返回类型(参数类型...)>` 是一个类型擦除的可调用对象包装器,能统一存放普通函数、lambda、函数对象(仿函数)、成员函数指针(配合 `std::bind` 或 lambda):

```cpp
#include <iostream>
#include <functional>

int add(int a, int b) { return a + b; }

struct Multiplier {
    int factor;
    int operator()(int x) const { return x * factor; } // 仿函数:重载了 () 的类
};

int main() {
    std::function<int(int,int)> f1 = add;                    // 包装普通函数
    std::function<int(int,int)> f2 = [](int a, int b) { return a - b; }; // 包装 lambda
    std::function<int(int)> f3 = Multiplier{3};                // 包装函数对象

    std::cout << f1(3, 4) << " " << f2(3, 4) << " " << f3(5) << "\n"; // 7 -1 15

    using namespace std::placeholders;
    auto add5 = std::bind(add, 5, _1);    // 把第一个参数固定为 5,_1 是调用时才填的占位符
    std::cout << add5(10) << "\n";          // add(5,10) = 15

    auto addRev = std::bind(add, _2, _1);  // 交换参数顺序
    std::cout << addRev(1, 2) << "\n";       // add(2,1) = 3
}
```

```
7 -1 15
15
3
```

现代 C++ 更推荐用 lambda 替代 `std::bind`(可读性更好、更容易被编译器内联优化),`std::bind` 主要在维护旧代码或需要动态拼装可调用对象时还会遇到。`std::function` 的代价是有一定的运行时开销(类型擦除、可能的堆分配),性能敏感场景可考虑模板参数直接接受可调用对象。

## 七、可变参数模板与可变参数函数

```cpp
#include <iostream>
#include <cstdarg>

// C 风格可变参数(不推荐,类型不安全,需要调用者手动保证类型匹配)
double sumC(int count, ...) {
    va_list args;
    va_start(args, count);
    double total = 0;
    for (int i = 0; i < count; ++i) total += va_arg(args, double);
    va_end(args);
    return total;
}

// C++11 可变参数模板(推荐):递归展开,编译期类型安全
template<typename T>
T sumT(T last) { return last; }

template<typename T, typename... Rest>
T sumT(T first, Rest... rest) {
    return first + sumT(rest...);
}

// C++17 折叠表达式:更简洁的等价写法
template<typename... Args>
auto sumFold(Args... args) {
    return (args + ...);
}

int main() {
    std::cout << sumC(3, 1.0, 2.0, 3.0) << "\n"; // 6
    std::cout << sumT(1, 2, 3, 4) << "\n";         // 10
    std::cout << sumFold(1, 2, 3, 4, 5) << "\n";    // 15
}
```

```
6
10
15
```

`typename... Args` 是**模板参数包**,`Args... args` 是**函数参数包**,`args...` 在表达式中展开。`sizeof...(Args)` 可以在编译期取得参数个数。C++17 折叠表达式 `(args + ...)`(一元右折叠)是对参数包做二元运算符归约的简洁写法,避免手写递归终止函数。

## 八、参数传递方式的选择:值 / 指针 / 引用

```cpp
#include <iostream>
#include <string>

void byValue(std::string s) { s += " modified"; }              // 拷贝整个字符串,原对象不受影响
void byPointer(std::string* s) { if (s) *s += " modified"; }    // 需要判空,调用处要写 &s
void byRef(std::string& s) { s += " modified"; }                 // 直接操作原对象,不拷贝,无需判空
void byConstRef(const std::string& s) { std::cout << "read: " << s << "\n"; } // 只读大对象的标准做法

int main() {
    std::string a = "hello";
    byValue(a);
    std::cout << "after byValue: " << a << "\n";     // hello(未变,byValue 操作的是拷贝)

    byPointer(&a);
    std::cout << "after byPointer: " << a << "\n";     // hello modified

    byRef(a);
    std::cout << "after byRef: " << a << "\n";          // hello modified modified

    byConstRef(a);
}
```

```
after byValue: hello
after byPointer: hello modified
after byRef: hello modified modified
read: hello modified modified
```

选择原则:

- **小的、可平凡拷贝的类型**(`int`、`double`、指针本身、小 `struct`)直接按值传,拷贝比引用间接寻址还便宜。
- **需要修改调用者的对象**,优先用**引用**(`T&`):无需判空、语法比指针干净;只有在"可能不传"(可为空)或需要重新指向不同对象时才用指针。
- **只读的大对象**(`std::string`、`std::vector`、自定义大类)用 `const T&`,避免拷贝开销又防止误修改。
- 需要**转移所有权**(避免拷贝、允许"窃取"资源)时用右值引用 `T&&`(见第 5 章移动语义)。

## 九、返回值优化 RVO / NRVO

```cpp
#include <iostream>

struct Trace {
    Trace()  { std::cout << "构造\n"; }
    Trace(const Trace&) { std::cout << "拷贝构造\n"; }
    Trace(Trace&&) noexcept { std::cout << "移动构造\n"; }
    ~Trace() { std::cout << "析构\n"; }
};

Trace makeTrace() {
    Trace t;            // NRVO:具名返回值优化,编译器通常直接在调用者的存储位置构造 t,省去拷贝/移动
    return t;
}

Trace makeTraceTemp() {
    return Trace{};       // RVO:C++17 起标准强制保证省略拷贝(mandatory copy elision)
}

int main() {
    Trace a = makeTrace();
    Trace b = makeTraceTemp();
}
```

正常编译(允许省略)的输出——每次调用只看到一次"构造",没有任何拷贝/移动:

```
构造
构造
析构
析构
```

用 `-fno-elide-constructors` 关掉非强制的省略优化后,可以看到 NRVO 和"强制 RVO"的区别:

```
$ g++ -std=c++17 -fno-elide-constructors rvo.cpp -o rvo_noelide && ./rvo_noelide
构造        <- makeTrace 里构造局部变量 t
移动构造     <- return t; 把具名对象 t 移动到调用点(NRVO 被关闭后退化为一次移动)
析构        <- t 析构
构造        <- makeTraceTemp 里 Trace{} 直接构造(C++17 强制省略,即使关闭标志也无法阻止)
析构        <- b 在 main 结束时析构
析构        <- a 在 main 结束时析构
```

要点:C++17 起,函数返回一个**纯右值(prvalue)**临时对象(如 `return Trace{};`)时,标准**强制**要求编译器直接在调用者的目标存储上构造,不存在多余的拷贝/移动可供省略——这与 `-fno-elide-constructors` 无关。而返回一个**具名局部变量**(如 `return t;`)属于 NRVO,是标准**允许但不强制**的优化,大多数编译器在默认优化下都会做,但理论上可能因为控制流复杂(比如同一函数里有多条 `return` 语句返回不同的局部变量)而放弃优化,退化为一次移动构造(如果类型支持移动)或拷贝构造。
