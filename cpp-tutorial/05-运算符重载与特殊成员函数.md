# 运算符重载与特殊成员函数

本章覆盖运算符重载的写法与可重载运算符清单,以及"特殊成员函数"这套体系:拷贝/移动构造与赋值、Rule of Three/Five/Zero、`explicit` 防止隐式转换、类型转换运算符重载。这是 C++ 对象生命周期管理里最容易出 bug 的一块,务必逐条过一遍。

## 一、可重载运算符与写法示例

```cpp
#include <iostream>

class Vec2 {
public:
    double x, y;
    Vec2(double x = 0, double y = 0) : x(x), y(y) {}

    Vec2 operator+(const Vec2& o) const { return Vec2(x + o.x, y + o.y); }  // 二元 +
    Vec2 operator-(const Vec2& o) const { return Vec2(x - o.x, y - o.y); }  // 二元 -
    Vec2 operator-() const { return Vec2(-x, -y); }                          // 一元 -(取负)
    Vec2& operator+=(const Vec2& o) { x += o.x; y += o.y; return *this; }    // 复合赋值
    bool operator==(const Vec2& o) const { return x == o.x && y == o.y; }     // 相等比较(C++20 起自动生成 !=)
    double& operator[](int i) { return i == 0 ? x : y; }                       // 下标运算符

    friend std::ostream& operator<<(std::ostream& os, const Vec2& v) {        // 输出流运算符,必须是自由函数
        return os << "(" << v.x << ", " << v.y << ")";
    }
};

int main() {
    Vec2 a(1, 2), b(3, 4);
    std::cout << (a + b) << "\n";       // (4, 6)
    std::cout << (a - b) << "\n";       // (-2, -2)
    std::cout << (-a) << "\n";           // (-1, -2)
    a += b;
    std::cout << a << "\n";               // (4, 6)
    std::cout << (a == Vec2(4,6)) << "\n"; // 1
    std::cout << (a != b) << "\n";          // 1,C++20 起由 == 自动生成
    a[0] = 100;
    std::cout << a << "\n";                  // (100, 6)
}
```

```
(4, 6)
(-2, -2)
(-1, -2)
(4, 6)
1
1
(100, 6)
```

可重载运算符清单(几乎所有运算符都能重载):

| 类别 | 运算符 |
|---|---|
| 算术 | `+ - * / % ++ --` |
| 比较 | `== != < > <= >= <=>`(C++20 三路比较) |
| 逻辑/位运算 | `&& \|\| ! & \| ^ ~ << >>` |
| 赋值 | `= += -= *= /= %= &= \|= ^= <<= >>=` |
| 下标/调用/成员访问 | `[] () -> ->* ,` |
| 内存 | `new delete new[] delete[]` |
| 其他 | `""` (自定义字面量后缀,C++11) |

**不能重载**的运算符:`. .* :: ?: sizeof typeid`。重载运算符应尽量保持与内置语义直觉一致(例如 `+` 不应该产生副作用),输出流运算符 `<<`/`>>` 因为左操作数是 `ostream&` 而非自定义类型,只能写成自由函数(或 `friend`)。C++20 引入三路比较运算符 `<=>`("太空船运算符"),编译器可以由它自动生成 `< > <= >=`。

## 二、拷贝构造函数与拷贝赋值运算符

```cpp
class MyString {
public:
    MyString(const MyString& other);              // 拷贝构造:用已有对象初始化新对象
    MyString& operator=(const MyString& other);    // 拷贝赋值:把已有对象的内容赋给一个已存在的对象
};
```

两者的关键区别是**目标对象是否已经存在**:`MyString b = a;`(或函数传值/返回值)调用拷贝构造,在全新内存上构建对象;`d = b;`(`d` 已经是一个存活对象)调用拷贝赋值,需要先释放 `d` 原有资源、检查自赋值(`this == &other`)再拷贝。完整可运行示例见下一节。

## 三、移动构造函数与移动赋值运算符(C++11)

移动语义解决的问题:当右侧操作数是一个**即将销毁的临时对象**(或被 `std::move` 显式标记的对象)时,与其深拷贝它的资源,不如直接"偷"过来,把源对象置空即可——避免一次不必要的分配和拷贝。

```cpp
#include <iostream>
#include <cstring>
#include <utility>

class MyString {                      // Rule of Five:管理裸资源(char*)必须五个都写
public:
    MyString(const char* s = "") {
        len_ = std::strlen(s);
        data_ = new char[len_ + 1];
        std::strcpy(data_, s);
    }
    ~MyString() { delete[] data_; }                                          // 1. 析构函数

    MyString(const MyString& other) : len_(other.len_) {                     // 2. 拷贝构造
        data_ = new char[len_ + 1];
        std::strcpy(data_, other.data_);
        std::cout << "拷贝构造\n";
    }
    MyString& operator=(const MyString& other) {                             // 3. 拷贝赋值
        if (this == &other) return *this;    // 自赋值检查
        delete[] data_;
        len_ = other.len_;
        data_ = new char[len_ + 1];
        std::strcpy(data_, other.data_);
        std::cout << "拷贝赋值\n";
        return *this;
    }
    MyString(MyString&& other) noexcept : data_(other.data_), len_(other.len_) { // 4. 移动构造
        other.data_ = nullptr;   // 掏空源对象,避免它析构时把资源也 delete 掉
        other.len_ = 0;
        std::cout << "移动构造\n";
    }
    MyString& operator=(MyString&& other) noexcept {                          // 5. 移动赋值
        if (this == &other) return *this;
        delete[] data_;
        data_ = other.data_;
        len_ = other.len_;
        other.data_ = nullptr;
        other.len_ = 0;
        std::cout << "移动赋值\n";
        return *this;
    }

    const char* c_str() const { return data_; }
private:
    char* data_;
    size_t len_;
};

int main() {
    MyString a("hello");
    MyString b = a;               // 拷贝构造
    MyString c = std::move(a);     // 移动构造:a 被掏空,c 接管资源
    MyString d;
    d = b;                           // 拷贝赋值
    d = std::move(c);                 // 移动赋值
    std::cout << d.c_str() << "\n";
}
```

```
拷贝构造
移动构造
拷贝赋值
移动赋值
hello
```

`std::move` 本身**不移动任何东西**,只是把左值强制转换成右值引用(`static_cast<T&&>`),真正的"搬家"发生在接收方的移动构造/移动赋值函数体里。移动后的源对象处于"有效但未指定"的状态,只能安全地析构或重新赋值,不应再假设它的内容。

## 四、Rule of Three / Rule of Five / Rule of Zero

- **Rule of Three**(C++98/03 时代):如果一个类需要自定义**析构函数、拷贝构造函数、拷贝赋值运算符**三者中的任意一个(通常是因为手动管理裸指针等资源),那么这三个几乎肯定都需要自定义,否则编译器生成的默认版本会做浅拷贝,导致同一块资源被多次 `delete`(双重释放)。
- **Rule of Five**(C++11 起):加上**移动构造函数、移动赋值运算符**,变成需要考虑的五个特殊成员函数(上面 `MyString` 就是完整的 Rule of Five 写法)。声明了其中任何一个析构/拷贝/移动函数,编译器就会停止隐式生成移动版本(可能退化为拷贝,也可能直接被删除),因此这五个通常要么全写、要么一个都不写。
- **Rule of Zero**(现代 C++ 推荐做法):**不要自己管理裸资源**。让类的所有成员都是已经正确实现了 Rule of Five 的类型(`std::string`、`std::vector`、智能指针等),这样自己的类就一个特殊成员函数都不用写,编译器生成的默认版本(逐成员拷贝/移动/析构)天然就是正确的。

```cpp
class RuleOfZero {                     // 全用标准库成员管理资源,五个特殊成员函数全部不用写
    std::string name_;                  // std::string 自己管理内存,编译器生成的默认行为就是对的
public:
    RuleOfZero(std::string n) : name_(std::move(n)) {}
    const std::string& name() const { return name_; }
};

int main() {
    RuleOfZero r("Alice");
    RuleOfZero r2 = r;      // 编译器自动生成的拷贝构造(逐成员拷贝 std::string),正确且安全
    std::cout << r2.name() << "\n"; // Alice
}
```

```
Alice
```

实践建议:**默认写 Rule of Zero**,只有在实现资源管理类本身(比如自己写一个智能指针)时才需要 Rule of Five。

## 五、`explicit` 关键字防止隐式转换

单参数构造函数(或所有参数除第一个外都有默认值的构造函数)默认允许**隐式转换**——传参时会自动把匹配类型的值转换成该类对象,这经常导致意料之外的转换发生。`explicit` 关闭这种隐式转换,只允许显式构造:

```cpp
#include <iostream>

class Meters {
public:
    explicit Meters(double v) : value_(v) {}   // explicit:禁止隐式转换构造
    double value() const { return value_; }

    explicit operator double() const { return value_; } // 类型转换运算符(也建议加 explicit)

private:
    double value_;
};

void printMeters(Meters m) { std::cout << m.value() << "m\n"; }

int main() {
    Meters m(5.0);            // 显式构造,OK
    // Meters m2 = 5.0;        // 编译错误:explicit 构造函数禁止这种隐式转换写法
    // printMeters(5.0);       // 编译错误:同理,不能隐式把 double 转成 Meters

    double d = static_cast<double>(m); // 显式使用类型转换运算符
    std::cout << d << "\n";              // 5

    printMeters(Meters(3.0));             // 显式构造后传参,OK
}
```

```
5
3m
```

不加 `explicit` 直接传 `double` 给需要 `Meters` 的形参会报错(因为示例里加了 `explicit`):

```
error: no matching function for call to 'printMeters'
    printMeters(5.0);
note: candidate function not viable: no known conversion from 'double' to 'Meters' for 1st argument
```

## 六、类型转换运算符重载

`operator TargetType() const` 让自定义类型可以转换为其他类型(上例的 `operator double()`)。和转换构造函数一样,类型转换运算符也应该默认加 `explicit`(C++11 起支持),只在真正需要"隐式转换到 bool 用于条件判断"这类场景(如智能指针的 `operator bool()`)才考虑不加 `explicit`,否则很容易在算术表达式、函数重载决议里引发意外的隐式转换链,是经典的"惊讶最小原则"违反来源。
